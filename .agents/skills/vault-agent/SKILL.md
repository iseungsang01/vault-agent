# vault-agent 설정하기

사용자의 위키를 **읽기 전용으로 둘러본 뒤** 설정 파일 두 개를 만들고, `plan` 과 `--dry-run` 으로 결과를 보여 준다. 위키 노트 자체는 이 스킬이 고치지 않는다.

## 1. 위키를 파악한다

- 루트의 폴더 목록과 각 폴더의 노트 몇 개를 읽어 역할을 추정한다. 전형적인 역할은 네 가지다.
  - **기준**: 프로필·제약·현재 상태처럼 자주 바뀌지 않는 노트
  - **실행 계획**: 요일·주차·과목별로 할 일을 `[[링크]]` 로 엮은 노트 (씨앗 노트가 된다)
  - **날짜별 기록**: `YYYY-MM-DD_….md` 처럼 날짜로 시작하는 노트
  - **항목별 정본**: 종목·과제·실험처럼 항목 하나당 한 파일, "현재 기준"과 "다음 목표"가 있는 노트
- 사용자에게 확인할 것은 네 가지뿐이다. 나머지는 추정해서 제안한다.
  1. Codex 가 **절대 고치면 안 되는** 파일 (readOnly)
  2. **매번 읽어야 하는** 파일 (alwaysRead)
  3. 고쳐도 되는 폴더 (writableDirs) — 개인정보·사진·체형 기록 폴더는 넣지 않는다
  4. 새 기록 노트의 이름 규칙 (newNote)

## 2. 파일 두 개를 만든다

- `vault-agent.json` — `vault-agent.example.json` 을 바탕으로 1에서 정한 값으로 채운다. `readableDirs` 는 Codex 가 읽어도 되는 폴더 전부, `writableDirs` 는 그 부분집합이다. `linkDepth` 는 보통 1, 정본 노트끼리 링크가 많으면 2.
- `vault-agent.instructions.md` — `instructions.example.md` 를 바탕으로 사용자의 용어(종목/과제/실험)와 노트 구조에 맞게 고쳐 쓴다. 다음 규칙은 빼지 않는다: 허용 목록 밖 금지, 추측 금지("미기록"), 읽기 전용 파일 수정 금지, 긴 해석은 답변에만, 날짜별 기록은 최근 N회만.

## 3. 보여 주고 끝낸다

```
node vault-agent.mjs plan --seed "<실행 계획 노트>" --message "<사용자가 보낼 법한 한 문단>"
node vault-agent.mjs run  --seed "<같은 노트>" --message "<같은 문단>" --dry-run
```

`plan` 은 읽을 파일과 고칠 수 있는 파일 목록만 보여 준다. 사용자가 목록에 동의하면 `--dry-run` 으로 diff 를 보여 준다. 실제 반영(`run`)과 되돌리기(`undo`)는 사용자가 직접 실행한다. 상시 서버나 스케줄러를 만들지 않는다.
