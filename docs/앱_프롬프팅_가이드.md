# 운동 기록장 앱 프롬프팅 가이드

이 문서는 현재 앱에서 확인되는 제품 방향을 바탕으로, 앱을 처음 구상하고 AI와 함께 기틀을 세웠다면 어떤 순서로 프롬프팅할 수 있었을지 재구성한 가이드다. 아래 문구는 실제 과거 대화의 원문이 아니라 재사용을 위한 예시다. 색상·간격·버튼 모양 같은 시각 세부사항은 초기 프롬프트에서 고정하기보다 동작하는 초안을 본 뒤 점진적으로 정한다.

## 1. 앱 프롬프트를 만들기 위한 프롬프트

아이디어가 아직 거칠 때 먼저 AI에게 구현을 시키지 않고, 목적과 필수 조건을 정리해 구현 프롬프트를 만들게 한다.

```text
내가 만들고 싶은 앱 아이디어를 실제로 구현할 수 있는 앱 제작 프롬프트로 정리해 줘.

먼저 아래 항목을 중심으로 아이디어를 구조화해 줘.
- 누가 어떤 상황에서 앱을 쓰는가
- 앱이 가장 먼저 해결해야 할 문제는 무엇인가
- 첫 버전에 꼭 필요한 사용자 흐름과 기능은 무엇인가
- 사용자 데이터는 어디에 저장하고, 계정·인터넷 연결이 꼭 필요한가
- 목표 플랫폼과 현재 프로젝트의 기술·파일 구조는 무엇인가
- 개인정보, 데이터 손실, 외부 연동에서 지켜야 할 조건은 무엇인가

초기 구현 프롬프트에는 제품 목적, 핵심 흐름, 필수 동작, 데이터 조건, 기술 제약만 넣어 줘. 내가 아직 정하지 않은 시각 디자인 세부사항은 임의로 확정하지 말고, 기본 가정으로 남기거나 꼭 필요한 경우에만 질문해.

먼저 정리된 요구사항과 모호한 가정을 짧게 보여준 다음, 코딩 에이전트에 그대로 전달할 수 있는 하나의 구현 프롬프트를 작성해 줘. 이 단계에서는 코드를 수정하지 마.
```

## 2. 앱의 기틀을 잡는 초기 구현 프롬프트

운동 기록장 같은 앱이라면 첫 프롬프트는 화면을 픽셀 단위로 지시하기보다, 사용자가 운동 중 무엇을 하고 앱이 무엇을 보존해야 하는지 전달한다.

```text
휴대폰에서 쓰는 한국어 운동 기록 앱의 작동하는 첫 버전을 만들어 줘.

운동할 때 오늘의 루틴을 고르고, 운동 종목마다 세트의 무게와 반복 횟수를 입력하고 완료를 표시할 수 있게 해 줘. 운동이 끝나면 그날 기록을 저장하고, 나중에 날짜별 기록과 종목별 변화도 다시 볼 수 있어야 해.

처음 쓰는 사람은 계정이나 토큰을 만들지 않고 바로 시작할 수 있게 해 줘. 기본은 기기 로컬 저장으로 하고, 이 기록이 다른 기기와 자동 동기화되지 않는다는 점을 알려 줘. 가능하면 데이터를 파일로 백업하고 복원할 길도 제공해 줘.

주 대상은 Android 휴대폰이야. 현재 프로젝트의 구조와 기술을 먼저 살펴보고 그 안에 맞춰 구현해 줘. 이미 동작하는 기능이나 데이터 형식이 있다면 확인 없이 갈아엎지 말아 줘.

우선 핵심 사용 흐름이 끝까지 작동하는 단순한 초안을 만들어 줘. 디자인은 읽기 쉽고 터치하기 편한 기본값으로 시작하고, 세부 색상·모션·간격은 초안을 본 다음 별도 요청으로 다듬을게. 구현 후에는 무엇을 만들었고 어떻게 확인했는지 요약해 줘.
```

## 3. 초안을 본 뒤 조금씩 구체화하는 후속 프롬프트

기틀이 실행되면 화면을 실제로 써 보고 한 번에 한 주제씩 수정한다. 아래는 현재 앱 방향에 맞춘 예시이며, 실제 작업에서는 불편했던 점을 구체적으로 바꿔 쓴다.

### 운동 중 조작 흐름

```text
운동 중에는 폰을 한 손으로 쓰는 상황이 많아. 기록 화면에서 세트 완료와 다음 종목 이동을 빠르게 할 수 있게 흐름을 다듬어 줘. 종목이 많아도 현재 운동과 입력 중인 세트가 눈에 잘 들어오게 해 줘. 기존 기록 저장 방식은 유지해 줘.
```

### 기록 정리와 통계

```text
지난 기록을 날짜별로 다시 찾기 쉽게 해 줘. 달력에서 운동한 날을 구분하고, 주간 운동 횟수와 세션별 완료 종목·세트·메모를 볼 수 있게 해 줘. 종목별로 무게나 반복 횟수의 변화를 확인할 화면도 추가해 줘. 새 화면은 기존 기록 데이터로 채울 수 있어야 해.
```

### 시각 디자인 조정

```text
기능 흐름은 유지하면서 모바일 화면을 더 편하게 다듬어 줘. 작은 화면에서도 주요 입력과 완료 버튼이 잘 보이고 누르기 쉽도록 해 줘. 대비가 충분한 다크 테마를 기본으로 하고, 밝은 화면과 시스템 테마 선택도 지원해 줘. 먼저 현재 화면을 살펴보고 구체적인 간격과 색상은 전체가 일관되도록 정해 줘.
```

### 로컬 우선과 백업

```text
로그인하지 않은 사용자도 바로 이용할 수 있는 게스트 모드를 추가해 줘. 게스트 기록은 그 기기에만 저장하고, 앱 삭제나 데이터 초기화 시 사라질 수 있다는 점을 설정에 알려 줘. JSON 백업 내보내기와 복원을 제공하고, 복원 전에 현재 데이터를 덮어쓴다는 확인을 받아 줘. GitHub 연동이 이미 있다면 선택 기능으로 남겨 두고 게스트 데이터와 섞이지 않게 해 줘.
```

### 마무리와 회귀 방지

```text
방금 변경한 부분을 확인하고, 기존 기록을 열고 새 기록을 저장하는 흐름이 그대로 유지되는지 살펴봐 줘. 오류가 있으면 고쳐 줘. 새 기능의 동작, 데이터 저장 위치, 사용자가 알아야 할 제한을 README에도 짧게 반영해 줘.
```

## 프롬프팅 순서 요약

```text
아이디어 정리 프롬프트
        ↓
목적·사용자·핵심 흐름·데이터 제약이 담긴 초기 구현 프롬프트
        ↓
실행 가능한 최소 앱 초안
        ↓
실제 사용 후 흐름 → 통계 → 시각 디자인 → 백업 순으로 점진 개선
```

처음부터 모든 디자인 결정을 프롬프트에 넣기보다, 먼저 핵심 흐름과 데이터 원칙을 고정하고 화면을 사용해 본 뒤 불편을 구체적인 후속 요청으로 바꾸는 방식이다.

## 현재 구현 기준

- 플랫폼: Capacitor Android 앱, 정적 웹 화면
- 시작 모드: 게스트
- 게스트 기본 루틴: `docs/guest-plan.json`
- 게스트 저장 및 백업: 앱 `localStorage`, JSON 파일 내보내기·가져오기
- 선택 연결: GitHub Contents API, `app/plan.json`, `app/history.json`, `inbox/sessions/`
- 앱 빌드·배포: `.github/workflows/android.yml`
- 저장소에 올라온 세션의 옵시디언 반영은 볼트의 앱 동기화 흐름을 따른다.

문서는 제품의 기틀과 프롬프팅 과정을 설명한다. 세부 동작은 코드와 함께 바뀔 수 있으므로 저장 방식이나 연동 경로를 변경하면 이 기준도 갱신한다. 공유 가능한 문서이므로 개인 운동 기록, 토큰, 비밀값은 넣지 않는다.
